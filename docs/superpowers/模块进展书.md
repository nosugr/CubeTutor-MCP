## 一、 项目定位与契约

基于 MCP 的 3D 智能魔方教学平台：
- **前端架构**：React 19 + TypeScript + Vite + Three.js 3D 魔方物理引擎（`cuber`）+ 摄像头实时扫面（`scanner.ts`）；
- **后端大脑**：Python FastAPI 后端（共享会话状态 / 三大求解引擎 / 真实 MCP Server / Agent 调度 / TTS 语音流）；
- **唯一状态真相**：Kociemba 54 格 facelet 字符串（`URFDLB` 序列，`SOLVED = U*9 R*9 F*9 D*9 L*9 B*9`）。

## 三、 模块 1 & 6 · 完成现状回顾

* **3D 物理模型（模块 1）**：
  - 基于 Three.js 原生 3D 魔方物理系统，启用 `cubelet.thickness = true` 实现高质感厚贴纸；
  - 采用标准的 **3/4 黄金教学观察视角**，U/F/R 三面立体比例自然清晰；
  - 具备原生手势层转阻尼与场景旋转交互，严格保持 54-facelet 契约。
* **摄像头视频流扫描录入（模块 6）**：
  - 基于 `src/cv/scanner.ts` 与 Python 端的 YOLOv8 目标检测，支持摄像头实时捕捉魔方并识别九宫格颜色；
  - 支持前置摄像头水平镜像翻转与 90° 旋转校正；
  - 提供 2D 展开图手动点色微调，确保 100% 准确录入。

## 六、 模块启动协作流程

后续每个模块启动时遵循以下标准流程：
1. **需求讨论**：先就该模块的交互形式、视觉效果或文案内容与用户展开讨论，达成共识；
2. **编写设计规范（Spec）**：在 `docs/superpowers/specs/` 下形成专项设计稿，经用户批准；
3. **编写实施计划（Plan）**：在 `docs/superpowers/plans/` 下拆分可打勾的施工步骤；
4. **编码与点验**：按计划执行，改完后运行 `pytest` 及前端浏览器功能点验；
5. **更新看板**：回写计划勾选与本进展书状态。
