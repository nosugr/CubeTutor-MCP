## 一、 总目标

交付可答辩演示的 **基于 MCP 的 3D 智能魔方教学工作台**：
- **3D 孪生**：具备基于 React 19 + Three.js 的高质量、极度丝滑的 3D 魔方数字孪生与动画物理系统；
- **多算法教学**：支持 3 种还原规则（新手层先法 7 阶段、CFOP 进阶法、Kociemba 最短极速解）并提供清晰的教学指引；
- **MCP 智能大脑**：基于 **真实 MCP (Model Context Protocol) 协议** 由 AI Agent 调度工具指挥还原全过程，并生成逐步中文讲解；
- **AI 语音教学**：集成 TTS 语音流式合成，实现“边走步、边转 3D、边听中文语音讲解”；
- **视觉多模态录入**：支持基于 YOLOv8 / 摄像头视频流实时扫描与手动点色录入真实魔方状态；
- **全链路健壮性**：具备失败处理与优雅降级能力，提供可流畅跑通的答辩演示专属路径。

## 二、 八大模块定位与说明

### 模块 1 · 魔方 3D 模型
* **定位**：浏览器内呈现清晰、平滑、可交互的三阶魔方数字孪生，作为教学与演示的视觉主体。
* **主要内容**：浅色柔光微渐变背景、3/4 黄金教学观察视角、黑色倒角骨架、圆角半哑光厚贴纸（Thick Stickers）质感、阻尼手势旋转与平滑复位。
* **状态**：✅ **已优化就位**（完全基于 `cuber` 原生 3D 物理引擎，底层 54-facelet 契约严格保持）。

---

### 模块 2 · 前端布局与视觉风格
* **定位**：基于现代玻璃拟态 UI，搭建信息架构清晰、操作层级明确的中文工作台界面，适配答辩投影与演示。
* **主要内容**：3D 主视区、底栏控制区、右侧抽屉式「魔方助手」教学面板（边缘可拉伸调整宽度、左侧右键收起、历史对话持久化）、Emotion Ball 情绪球 Avatar。
* **状态**：✅ **已优化就位**。

---

### 模块 3 · 规则写入与规则教学说明
* **定位**：提供三种可用的还原规则（新手层先法 7 阶段 / CFOP 进阶法 / Kociemba 最优解），并向学习者解释各阶段的目标与逻辑。
* **主要内容**：规则对比卡片、还原阶段释义、基于 6 处固定中心块颜色基准（顶白、底黄、正绿、背蓝、左橙、右红）的大白话动作手势教学与 3x3 颜色九格精准索引。
* **状态**：✅ **已优化就位**。

---

### 模块 4 · Agent LLM 接入（含 MCP）
* **定位**：Agent 通过真实 MCP 协议调用核心工具指挥还原，并在配置大模型时生成通顺口语化的逐步中文教学讲解。
* **主要内容**：4 个标准 MCP 工具、SSE 流式打字机输出、DeepSeek R1 深度思考折叠卡片、主流 Agent 风格的 4 阶段聚合调用轨迹与 Cherry Studio 级多服务商配置中心。
* **状态**：✅ **已优化就位**。

---

### 模块 5 · Agent TTS 语音播报
* **定位**：语音播报能力，将当前步的教学讲解文字转化为语音流输出。
* **主要内容**：采用浏览器原生 Web Speech API 高清中文合成，智能过滤 Markdown 符号，支持全局伴读开关（默认静音）与单条气泡独立播放/重播。
* **状态**：✅ **已优化就位**。

---

### 模块 6 · 用户上传与状态同步
* **定位**：支持用户通过摄像头实时扫描或手动点色录入真实魔方状态，经合法性校验后同步至 3D 模型与后端会话。
* **主要内容**：基于 YOLOv8 / 摄像头视频流实时扫描（`src/cv/scanner.ts`）、六面朝向引导、点色纠错与中心块锁定保护、非法状态明确提示与改色引导。
* **状态**：✅ **基础链路与扫面组件已就位**。

---

### 模块 7 · 失败处理与优雅降级
* **定位**：确保全链路关键异常均有清晰、友好的反馈与恢复路径，杜绝白屏与静默失败。
* **主要内容**：TaskGroup 协程容错自动降级、全空间 24 种物理姿态动态中心归一化（解决翻转魔方 centers 校验）、无 Key 智能引导。
* **状态**：✅ **已优化就位**。

---

### 模块 8 · Demo 演示界面与流程
* **定位**：为答辩与演示提供一条少干扰、强叙事、可在数分钟内完整流畅跑通的演示路径。
* **主要内容**：完整打通“一键打乱 → 摄像头扫描/手动调整 → MCP 求解推演 → 分步 3D 动画同步与大白话语音伴教”全链路演示路径。
* **状态**：✅ **已优化就位**。

## 四、 协作与推进原则

1. **先讨论，后出 Spec**：各模块启动前，先与用户讨论具体交互与呈现方式，并在 `specs/` 编写设计规范，经确认后再编写 `plans/` 执行。
2. **渐进细化**：后续针对各模块的详细验收指标直接落实到对应的专项 `spec` 与 `plan` 中。
3. **保持总览精简**：本任务书作为顶层框架保持稳定，不频繁写入底层代码实现细节。
