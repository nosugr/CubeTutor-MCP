## 1. 一句话目标

做一个**浏览器里的 3D 魔方工作台**：用户拍六面同步到仿真，选择还原规则后，由 **Agent 通过 MCP 工具**读取仿真状态并指挥逐步还原；界面提供文字讲解，可选语音播报，并能**自动演示完整还原过程**（含播放控制）。

本项目对齐课程选题方向：**MCP + 魔方教学**（数字孪生仿真替代蓝牙硬件传感，答辩时可说明数据源可替换）。

## 2. 已确认需求

### 2.1 页面与优先级

| 优先级 | 内容 | 说明 |
|--------|------|------|
| P0 | 3D 魔方工作台 | 本轮主交付；总览/展示页延后 |
| P1 | 产品总览页 | 以后补课题介绍与入口，不阻塞核心 |

### 2.2 功能清单（P0）

1. **3D 仿真魔方**  
   - 键盘按层转动（键位：`U/D/L/R/F/B`，`Shift` + 键为反向；实现时可微调）。  
   - 视角拖拽/缩放（沿用常见 OrbitControls 交互）。  
   - **随机打乱按钮**（在 3D 旁）：一键把仿真拧成随机**合法**乱序；不上传照片也能完整体验还原演示。打乱时若正在播放则先停播。

2. **状态录入：拍 6 张 + 点色修正**  
   - 一面一张照片，识别颜色后写入仿真。  
   - 识别后必须允许用户点击色块修正。  
   - 同步前做**合法状态检查**；非法则拒绝进入还原，并提示重拍或改色。  
   - 与「随机打乱」二选一入口：都能进入后续还原流程。

3. **三种可切换的还原规则**  
   - 新手层先法（教学向）  
   - 速拧 CFOP（Cross → F2L → OLL → PLL）  
   - 电脑近最优解（Kociemba 两阶段）  
   - 用户在界面选择当前规则；自动演示与 Agent 讲解都按所选规则走。

4. **自动演示全过程**  
   - 按当前规则生成步骤序列，在 3D 上逐步执行。  
   - 播放器：**播放 / 暂停 / 上一步 / 下一步 / 速度**。

5. **指导方式：单向讲解**  
   - 默认文字显示当前步讲解。  
   - 可开关语音：把当前讲解念出来（TTS）。  
   - **不做**多轮自由对话追问（可列为后续增强）。

6. **Agent + MCP**  
   - Agent 是「指挥」：通过 MCP 工具读状态、取解法、执行一步，再生成该步人话讲解。  
   - 大模型厂家**不绑死**，配置可切换。

### 2.3 明确不做（本轮）

- 产品总览落地页（延后）  
- 蓝牙智能魔方 / 硬件传感  
- 用户账号、排行榜、多阶魔方  
- 完整对话式答疑（可追问「为什么」）  
- 单张斜角照片一次识别六面（风险过高）

## 3. 整体形态

```
┌─────────────────────────────────────────────┐
│  浏览器：CubeTutor 工作台                      │
│  3D 魔方 + 随机打乱 │ 六面拍照/点色 │ 规则切换 │
│  播放器 │ 讲解文字 │ 语音开关                   │
└──────────────────┬──────────────────────────┘
                   │ HTTP / MCP
┌──────────────────▼──────────────────────────┐
│  Python 服务                                 │
│  状态模型 │ 合法校验 │ 三种出步骤器            │
│  MCP 工具 │ Agent（工具调用 + 写讲解）         │
│  TTS 适配层（可换厂家）                        │
└─────────────────────────────────────────────┘
```

**分工原则**

- 浏览器：看得见、摸得着的交互与动画。  
- Python：算得清、讲得清的规则、工具与 Agent。  
- 数字孪生：真实魔方状态以仿真 54 格为准；照片只是录入手段。

## 4. 核心概念（非算法细节）

### 4.1 状态表示

- 采用与常见求解器一致的 **54 面色串**（facelet）：六面各 9 格，顺序约定与 Kociemba 定义对齐（`U…R…F…D…L…B…`）。  
- 3D 模型、校验器、三种出步骤器、MCP `get_cube_state` **共用同一表示**，避免两套状态。

### 4.2 合法状态

任意涂色不一定能还原。同步与开还原前必须校验（置换奇偶、角块朝向、棱块朝向等群约束的工程实现）。  
非法 → 明确错误提示，不开始演示。

### 4.3 「还原规则」在系统里是什么

不是一句口号，而是三个**可替换的出步骤器**：

| 规则 | 对用户的意义 | 系统产出 |
|------|----------------|----------|
| 新手层先法 | 按层教学，好懂 | 分阶段步骤 + 阶段说明 |
| CFOP | 速拧主流法 | 按 Cross/F2L/OLL/PLL 分段的步骤 |
| 电脑速解 | 短、炫「智能」 | Kociemba 近最优公式序列 |

每种规则输出统一结构的「步骤列表」（一步 = 一次层转 + 可选讲解素材），播放器与 Agent 只消费这个统一结构。

## 5. MCP 工具（第一版）

先做 4 个，够支撑「Agent 指挥还原」：

| 工具 | 作用 |
|------|------|
| `get_cube_state` | 读取当前 54 格状态 |
| `validate_state` | 检查是否合法可还原 |
| `get_solution` | 按指定规则返回完整步骤列表 |
| `apply_move` | 执行一步层转，更新仿真并驱动前端动画 |

> 若教学演示时发现「一次拿整解」不利于逐步讲，实现阶段可再补 `get_next_step`；本架构预留同一出步骤器即可扩展，不提前膨胀工具面。

## 6. 主用户流程

### 6.1 录入并同步

1. 用户进入工作台（还原态或上次状态）。  
2. 依次拍摄/上传 6 面 → 自动识别颜色 → 预览在展开图或 3D 上。  
3. 点色修正 → 点「同步到魔方」。  
4. 后端校验：合法则写入仿真；非法则提示原因（如「棱块朝向不合法，请检查照片」）。

### 6.2 选择规则并自动还原

1. 选择：新手 / CFOP / 电脑速解。  
2. 点「开始还原」。  
3. Agent 经 MCP：读状态 → 校验 → 取该规则解法 → 逐步 `apply_move`。  
4. 每一步：更新 3D、展示文字讲解；若开语音则 TTS 朗读。  
5. 用户可用播放器干预：暂停、单步、调速、回退。

### 6.3 随机打乱后还原（免拍照）

1. 点「随机打乱」→ 后端（或等价逻辑）生成一串随机合法招式并应用到仿真，3D 播完打乱动画。  
2. 用户选规则 →「开始还原」→ 与 6.2 相同。

### 6.4 仅手动探索（无 Agent）

- 键盘自行拧方，用于熟悉手感或对比；不强制走 Agent。

## 7. 错误与边界

| 情况 | 处理 |
|------|------|
| 照片缺面、模糊、偏色 | 识别置信低时强制进入点色修正；不允许静默错同步 |
| 同步后非法状态 | 拒绝还原，指出需检查的面/块类型级提示（实现时定文案） |
| 求解超时/失败 | 提示更换规则或检查状态；播放器保持可退出 |
| 模型 API 不可用 | 降级：仍可用规则引擎出步骤 + 模板讲解，Agent 文案关闭并提示 |
| TTS 不可用 | 仅保留文字讲解 |

## 8. 技术选型（骨架级）

| 层级 | 选型意向 | 理由 |
|------|-----------|------|
| 前端 | 静态/轻前端 + Three.js | `web/` 自研工作台（Three.js CDN）；课程 Demo 够用 |
| 后端 | Python | Kociemba 生态成熟；MCP / Agent 好接 |
| 求解 | 自研/移植层先法与 CFOP 步骤器 + `RubikTwoPhase`（Kociemba） | 三种规则可落地 |
| Agent | 可切换的 Chat/Tools API | 厂家不绑死 |
| TTS | 可切换适配层 | 与 LLM 解耦 |
| 颜色识别 | 先做「前端取色 + 简单聚类/阈值」+ 强制手改 | 避免一上来重 CV；不准也能演示 |

## 9. 成功标准（怎样算做完 P0）

1. 键盘可稳定拧动 3D 魔方。  
2. 「随机打乱」后状态合法，可不上传照片直接走还原演示。  
3. 六面照片 + 点色修正后能同步；非法状态进不了还原。  
4. 三种规则都能给出可播放的步骤，并完成自动演示（含播放/暂停/单步/速度）。  
5. Agent 能通过 MCP 四工具走通「读状态 → 取解 → 逐步执行 → 输出讲解」。  
6. 文字讲解默认可用；语音开关在配置了 TTS 时可播。  
7. 模型或 TTS 挂掉时有降级，不白屏。
